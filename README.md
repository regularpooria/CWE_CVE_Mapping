# CWE to CVE Mapping Project

Map CVE (Common Vulnerabilities and Exposures) descriptions to CWE (Common Weakness Enumeration)
weaknesses in the CWE-699 *Software Development* view. The project spans the full pipeline: scraping the
CWE taxonomy, building and publishing a CVE-to-CWE dataset, and fine-tuning a hierarchy-aware embedding
model (**HiCWE**) that retrieves the most likely CWE for a given CVE description.

## Repository layout

```
dataset/                  notebooks + uploads that build the Hugging Face datasets
scrapers/                 scrapes the CWE-699 hierarchy from cwe.mitre.org -> CWE_SOFTWARE.json

models/                   model cards + notebook that pushes HiCWE to the Hub

```

## Dataset

The dataset is assembled from two upstream sources and published in three Hugging Face repositories.

### Sources

- **CVE-to-CWE mappings** — the [zefang-liu/cve-and-cwe-mapping-dataset](https://huggingface.co/datasets/zefang-liu/cve-and-cwe-mapping-dataset),
  enriched with CWE descriptions and parent-category information from the scraped CWE-699 hierarchy.
- **NVD CVE records** — raw CVE records scraped from the National Vulnerability Database.
- **CWE taxonomy** — the CWE-699 *Software Development* view (parents and children) scraped from
  `cwe.mitre.org` into `scrapers/scraped_data/CWE_SOFTWARE.json`.

### Published datasets

| Hugging Face repo | File | Description | Generated by |
| --- | --- | --- | --- |
| `regularpooria/CVE_CWE_Software_Mapping_Dataset` | `Global_Dataset.csv` | zefang-liu mappings cleaned + enriched with CWE descriptions & parents | `dataset/generate_dataset.ipynb` |
| `regularpooria/NVD_CVE_699_Dataset` | `NVD_CVE_Dataset.csv` | scraped NVD records resolved against CWE-699 | `dataset/push_nvd_to_huggingface.ipynb` |
| `regularpooria/CVE_CWE_Dataset` | `CVE_CWE_Dataset.csv` | the two sources joined on `CVE-ID` | `dataset/merge_datasets.ipynb` |

The merged dataset shares common columns (`CVE-ID`, `YEAR`, `CVE-DESCRIPTION`,
`CVE-DESCRIPTION-NORMALIZED`, `CWE-ID`, `CWE-DESCRIPTION`, `IS-IN-CWE699`) and keeps source-specific
columns (e.g. `PARENTS`, `CVSS-V3`, `SEVERITY` from the original dataset; `published`, `all_nvd_cwes`,
`true_children`, `true_categories` from NVD) as separate columns.

## Model fine-tuning

**HiCWE** (Hierarchy-Aware Contrastive CWE Encoder) is a sentence encoder fine-tuned to place a CVE
description close to its parent CWE category *and* its child CWE definition in a shared embedding space.
Two variants are released, both producing 384-dimensional embeddings:

| Model | Base | Role |
| --- | --- | --- |
| [`regularpooria/HiCWE-MiniLM-L6-v2`](https://huggingface.co/regularpooria/HiCWE-MiniLM-L6-v2) | `all-MiniLM-L6-v2` | lightweight default |
| [`regularpooria/HiCWE-MiniLM-L12-v2`](https://huggingface.co/regularpooria/HiCWE-MiniLM-L12-v2) | `all-MiniLM-L12-v2` | larger, best @1 |

### Training recipe (`A_hier_full`)

Fine-tuned with LoRA (rank 64, alpha 128, dropout 0) on the attention `query`, `key`, `value` and `dense`
projections, then merged back into the base weights so inference is a single forward pass of a plain
`SentenceTransformer`. Three `MultipleNegativesRankingLoss` datasets are trained jointly:

| Set | Anchor → positive | Hard negatives | Teaches |
| --- | --- | --- | --- |
| `cve_to_cwe` | CVE → its CWE | a sibling CWE + a look-alike from another category | stage-2 (child) ranking |
| `cve_to_category` | CVE → its parent category | nearest other category | stage-1 (category) ranking |
| `cwe_geometry` | CWE → a sibling CWE | look-alike from another category | siblings closer / other categories apart |

Hard negatives are mined with the *untuned* encoder. Child nodes are rendered from their description
and extended description; category nodes add their title, summary, and immediate-child titles.

**Hierarchy-aware training vs. hierarchy-guided inference.** The hierarchy is injected during training
by the three objectives above; the model learns to place a CVE near both its child CWE and its parent
category, and to keep sibling CWEs close while separating cross-category look-alikes. At inference, the
category ranking can optionally route the child search (top-`B` categories, then their children). That
routing is a retrieval constraint, not a learned hierarchy. With the wide beam used in the paper
(`B=20` of 40 categories) the hierarchical and flat child rankings are essentially identical, so the
flat ranking is the primary result; the training-objective ablation is the evidence that the hierarchy
matters. See `experiments/hierarchy_ablation.ipynb`.

### Controlled variables

- Split by CVE identifier (no multi-label CVE straddles splits), stratified on the primary CWE
- Fresh base model + LoRA initialization per variant
- 3 epochs, learning rate 1e-4, batch size 64, linear warmup (5%)
- Fixed random seed, `NO_DUPLICATES` batch sampler

### Inference

The recommended inference mirrors training: a two-stage search.

1. **Stage 1 (category)** — score every CWE *category* node and keep the top few (beam of 100).
2. **Stage 2 (child)** — rank the descendant children below those categories and return the top-k.

```python
from sentence_transformers import SentenceTransformer, util

model = SentenceTransformer("regularpooria/HiCWE-MiniLM-L6-v2")

cve = "The product does not neutralize special elements used in a SQL command."

# CWE node text = title + summary + immediate children titles
cwe_texts = [
    "Improper Neutralization of Special Elements used in an SQL Command ('SQL Injection'). "
    "The product constructs all or part of an SQL command using externally-influenced input ...",
    # ... one entry per CWE node
]

cve_emb = model.encode(cve, normalize_embeddings=True)
cwe_emb = model.encode(cwe_texts, normalize_embeddings=True)

scores = util.cos_sim(cve_emb, cwe_emb)[0]
top = scores.argsort(descending=True)[:5]
```

### Evaluation

Recall@k on CVEs disclosed **2023–2025**, unseen during training. Category recall uses the two-stage
search; child recall is reported both restricted to predicted categories (*hier.*) and over the full
taxonomy (*flat*).

| Target | Model | @1 | @3 | @5 |
| --- | --- | --- | --- | --- |
| Category | Majority class | 0.473 | 0.668 | 0.749 |
| Category | Baseline (untuned L6) | 0.235 | 0.408 | 0.508 |
| Category | Baseline (untuned L12) | 0.418 | 0.634 | 0.738 |
| Category | **HiCWE-MiniLM-L6-v2** | 0.763 | 0.865 | 0.896 |
| Category | **HiCWE-MiniLM-L12-v2** | **0.820** | **0.888** | **0.913** |
| Category | SOTA classifier (`mulliken/cwe-predictor`) | **0.820** | 0.875 | 0.881 |
| Child (hier.) | Majority class | 0.289 | 0.478 | 0.560 |
| Child (hier.) | Baseline (untuned L6) | 0.350 | 0.436 | 0.478 |
| Child (hier.) | Baseline (untuned L12) | 0.397 | 0.486 | 0.532 |
| Child (hier.) | **HiCWE-MiniLM-L6-v2** | 0.774 | 0.840 | 0.862 |
| Child (hier.) | **HiCWE-MiniLM-L12-v2** | **0.789** | **0.852** | **0.872** |
| Child (flat) | Majority class | 0.289 | 0.478 | 0.560 |
| Child (flat) | Baseline (untuned L6) | 0.362 | 0.453 | 0.497 |
| Child (flat) | Baseline (untuned L12) | 0.395 | 0.482 | 0.526 |
| Child (flat) | **HiCWE-MiniLM-L6-v2** | 0.771 | 0.839 | 0.862 |
| Child (flat) | **HiCWE-MiniLM-L12-v2** | **0.789** | **0.852** | **0.873** |
| Child (flat) | SOTA classifier (`mulliken/cwe-predictor`) | 0.678 | 0.775 | 0.799 |

Fine-tuning improves every target over the untuned encoder, and on the flat-child target both HiCWE
variants beat the SOTA classifier at a fraction of its size. On the finer-grained metrics, HiCWE-L12
reaches macro-F1 **0.225** (vs 0.069 for SOTA, with predictions outside the 304 test labels counted
as errors; the earlier 0.083 figure dropped those predictions), flat MRR **0.829** (vs 0.732), head
accuracy@1 **0.787** (vs 0.680), and tail accuracy@1 **0.216** (vs 0.000). The L6 variant is the
efficient default — the flat-child accuracy is essentially identical between the two sizes.

The SOTA classifier is a flat label classifier: its **flat child** score is its primary output (and
its category score is derived by mapping predicted children back to their parents), so it has no
hierarchical-child entry — there is no category stage to restrict. Hierarchical-child scores depend
on the beam width (`BEAM`, set to 20 in the notebook); rerun the notebook to refresh them after
changing it.

The comparison notebook also computes a **majority-class** baseline and a finer-grained error
analysis: **macro-F1**, **head vs. tail** accuracy@1, per-CWE precision/recall/F1, and a two-panel
**CWE-level confusion matrix** (SOTA vs. the best hierarchy-aware model) over the most frequent
CWEs, ordered by parent category so within-category confusion forms diagonal blocks. Full matrices
for every method are written to `confusion_<method>.csv` for the appendix. The hierarchical search
visits the top-20 categories and is vectorized, so evaluation no longer spends its time in
per-child Python loops.

`experiments/model_comparison.ipynb` reproduces these numbers and writes:

- `experiments/comparison_results.csv` — recall@k per method and target
- `experiments/mrr_results.csv` — flat MRR per method
- `experiments/per_cwe_results.csv` — per-CWE precision/recall/F1
- `experiments/confusion_<method>.csv` — full confusion matrices

### Hierarchy ablation and end-to-end simulation

- `experiments/hierarchy_ablation.ipynb` — separates hierarchy-aware training (three contrastive
  objectives; child-only vs full ablation) from hierarchy-guided inference (beam-size sweep over
  `B = 1..40` categories).
- `experiments/end_to_end_simulation.ipynb` — replaces the official NVD CWE with HiCWE top-1/top-3/top-5
  predictions for 2021–2025, recomputes the smoothed historical exploitation score from prior years,
  and compares PR-AUC/ROC-AUC/P@k/R@k/NDCG@k against the official-CWE, no-CWE, random, and EPSS
  rankings. It auto-detects CUDA, caches predictions, and downloads the 2020–2022 NVD records on first
  use; set `RUN_MODE="smoke"` for a 500-CVE/year check. The default exploitation labels are the public
  CISA KEV + ENISA EUVD KEV union; point `EXTRA_EXPLOITATION_CSV` at a local CSV to add VulnCheck,
  GreyNoise, or any other labels.
